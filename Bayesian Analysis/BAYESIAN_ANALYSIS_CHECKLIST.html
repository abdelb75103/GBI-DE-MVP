05Align the evidence using agreed scientific rules0 / 4
  • Review one type of issue at a time
    WhatWork through units, definitions, population labels and missingness in small batches.
    WhyYou can review a coherent decision without inspecting hundreds of unrelated edits.
    HowI show examples, the source evidence, proposed rule and affected records before applying it.
  • Resolve overlapping evidence and follow-up
    WhatIdentify reused participants, linked reports and incomplete observations.
    WhyCounting the same evidence twice overstates certainty.
    HowRecord source families and inclusion roles, align numerator and exposure periods, and log follow-up and reporting completeness.
  • Check derived values and study limitations
    WhatValidate calculations and assess relevant weaknesses in each source.
    WhyReported totals, rates and severity summaries are not interchangeable.
    HowKeep formulas and evidence locators, retain uncertainty, and use an agreed appraisal tool. Never substitute a median for a mean or invent missing precision.
  • Apply and verify each approved batch
    WhatMake only the agreed changes.
    WhyScientific judgement must remain visible.
    HowUse saved scripts and exact before-and-after records, verify untouched fields, and review failures before the next batch. Keep unresolved evidence flagged instead of guessing.

07Test the models before trusting real-data results0 / 4
  • Write the model recipe and pass rules
    WhatSpecify each model, its assumptions, starting expectations and numerical checks.
    WhyWe need a fair test agreed before the final fit.
    HowI translate the choices into plain English; we lock the technical specification, practical tolerances, comparison rules and fallback actions alongside it. Specify the conventional statistical comparison too, including how it handles zero injuries, related records, weights and uncertainty.
  • Check the proposed burden options first
    WhatAssess the proposed models for total days lost against the available measurements and follow-up.
    WhyA plausible model name does not guarantee a suitable model.
    HowTest eligible options on simulated data; choose by the frozen rules. If unsuitable, bring a justified alternative or descriptive fallback to you.
  • Try situations where the answer is known
    WhatGenerate artificial studies with known patterns and the actual study structure.
    WhyThis reveals coding mistakes and unsupported complexity.
    HowCheck recovery, uncertainty and how information is shared; include unusual disciplines, sparse evidence and near-zero differences. Simplify levels that cannot be supported.
  • Inspect what the assumptions predict
    WhatShow plausible rates and extreme cases before fitting the real outcomes.
    WhyApparently mild assumptions can imply implausible injuries or days lost.
    HowReview simulated plots and code checks, pin the PyMC environment, and save the approved specification. Stan remains optional only if time and complexity permit.

08Fit and check the two main analyses0 / 4
  • Fit supported incidence models
    WhatEstimate injury frequency for the approved settings.
    WhyThese are the first main results.
    HowRun the validated PyMC code on frozen inputs with saved seeds and settings. Start with supported components and add only approved levels.
  • Check the incidence results before proceeding
    WhatCheck that repeated sampling runs agree and predictions resemble the observed evidence.
    WhyA completed run can still be unreliable.
    HowReview numerical sampling checks, unexpected patterns, extreme predictions and the frozen pass limits. Fix failures before accepting the results.
  • Fit and check the supported burden model
    WhatEstimate days lost using the route accepted in step 7.
    WhyBurden requires its own evidence and checks.
    HowApply the same disciplined fit-and-review process, including zeros, large totals and follow-up limitations. Use the agreed descriptive route if no model passed.
  • Review the main results together
    WhatExplain estimates, uncertainty and limits in plain English.
    WhyWe need to distinguish what the evidence supports from what remains uncertain.
    HowShow the main plots with the diagnostic report. Record your acceptance of each analysis before treating it as a provisional result.

09Find out which conclusions survive reasonable changes0 / 4
  • Run the agreed alternative assumptions
    WhatRepeat the planned checks with alternative priors, sharing assumptions and evidence restrictions.
    WhyA headline may depend on one fragile choice.
    HowUse the same targets and report both the conclusion change and evidence lost. Include follow-up and study-quality restrictions where evaluable.
  • Compare settings only where they genuinely align
    WhatCheck overall results against their complete match/training components.
    WhyDifferent populations or omitted settings can create misleading discrepancies.
    HowUse the same population, period and definition. Include all relevant settings or label the check inapplicable; do not treat separate model runs as a joint probability calculation.
  • Test prediction without giving away the answer
    WhatTest the kind of prediction we intend to report.
    WhyRetaining related records can make a model look better than it is.
    HowFor a new study, hold out its whole independent source family. Compare models on the same observations and report how uncertain the comparison is.
  • Add secondary results only where supported
    WhatExamine category patterns and linked frequency/severity if eligible.
    WhyThese should explain the main results without adding unsupported claims.
    HowCheck completeness and comparability first, then use the pre-specified models and validations. Keep incomplete category reporting descriptive.

10Reproduce, document and approve the final release0 / 4
  • Rerun everything from the saved starting files
    WhatRebuild the analysis in a clean environment.
    WhyAnother researcher must be able to repeat it.
    HowFollow one documented sequence from frozen inputs to tables and figures, using pinned versions, saved settings and seeds. Check agreement within the pre-agreed numerical tolerances.
  • Check every reported number and claim
    WhatTrace the report back to its generated outputs.
    WhyCopying values by hand introduces errors.
    HowGenerate tables and figures from saved results, verify units and intervals, and link limitations to the evidence. Report the agreed conventional comparison alongside the Bayesian results, including its limits. Obtain an independent review of the final analysis and reporting.
  • Package the methods, code and audit trail
    WhatKeep a complete reproducibility bundle.
    WhyFinal code alone cannot explain how evidence became a result.
    HowInclude permitted inputs and identifiers, dictionary, transformations, model equations and priors, package/compiler versions, seeds, diagnostics, sensitivities, decisions and linked outputs. State any data-access restrictions.
  • Approve the release and how future updates work
    WhatSign off the final interpretation and update rules.
    WhyLiving evidence needs versioned results.
    HowYou approve the release and update cadence. Retain each earlier version; rerun the full updated evidence with the original priors unless an amendment is approved. Never count old data twice.
